# md2pptx

**Markdown と PowerPoint テーマ（pptx / thmx）から発表スライド（pptx）を生成するツール。**

スライドのデザインのおおもとは PowerPoint テーマで、配色・フォントはテーマに委ねます。
内容は Markdown で書き、行頭の見た目から段落種別（箇条書き・採番・結論行）を判定します。
表・フロー図・2カラム・タイトル改行にも対応します。

```
theme.pptx  ┐
            ├─▶  md2pptx  ─▶  out.pptx
input.md    ┘
```

## 特徴

- **テーマ駆動**：pptx（または thmx）の配色・フォント・レイアウトをそのまま使用
- **行頭マーカー記法**：`-` 箇条書き / `1.`・`①`・`(1)` 採番 / `→` 結論行 を見た目で自動変換
- **表**：Markdown 標準テーブル（ヘッダ着色・列幅指定）
- **フロー図**：独自の ` ```flow ` ブロックで box・矢印・キャプションを宣言的に記述
- **2カラム**：`<!-- @col -->` で「2 つのコンテンツ」レイアウト
- **発表者ノート**：` ```note ` ブロックでオーラル原稿をスライドと一緒に版管理
- **相対サイズ**：`{+1}`/`{-2}` で行ごとに強調・縮小（テーマ基準の相対段数のみ。絶対
  pt は持たない）
- **自動調整**：本文の標準フォントサイズに揃え、収まらない表・図は段階的に小さくして収める
- **はみ出し防止**：地の文がスライド外へあふれない

## 必要環境

- Python 3.11+
- [python-pptx](https://python-pptx.readthedocs.io/) 1.0 以上（インストール時に自動導入）
- [PyYAML](https://pyyaml.org/)（同上）

## インストール

`md2pptx` コマンドとして使えるようにするには、リポジトリのルートで次のいずれかを実行します。

```bash
# 推奨：pipx で隔離環境へインストール（依存も自動導入・PATH に md2pptx が入る）
pipx install .

# もしくは通常の pip（venv 推奨）
pip install .

# 開発用（編集が即反映される editable インストール）
pip install -e .
```

> pipx が無い場合は `brew install pipx`（macOS）や `python3 -m pip install --user pipx`
> で導入できます。インストールせずに試すだけなら、依存（`pip install python-pptx pyyaml`）を
> 入れたうえで `python3 -m md2pptx …` でも実行できます。

## 使い方

```bash
# テーマ（.pptx か .thmx）と Markdown を指定して pptx を生成
md2pptx input.md --theme theme.pptx -o out.pptx

# テーマ・出力先はフロントマターにも書ける（CLI 引数が優先）
md2pptx input.md

# インストールせず開発中に実行する場合
python3 -m md2pptx input.md
```

| オプション | 説明 |
|---|---|
| 位置引数 | 入力 Markdown ファイル |
| `--theme PATH` | テーマファイル（`.pptx` / `.thmx` 両対応）。フロントマター `theme:` を上書き |
| `-o, --output PATH` | 出力 pptx。フロントマター `output:` を上書き |
| `--keep-base PATH` | `.thmx` から作る中間 base pptx を破棄せず保存（デバッグ用） |
| `--pdf` | pptx 生成後に PDF も作る。出力先は出力 pptx と同じ場所・同じ名前の `.pdf` |
| `--pdf-output PATH` | PDF の出力先を指定する。単独で指定しても PDF を作る（`--pdf` は不要） |
| `--pdf-converter NAME\|COMMAND` | PDF 変換器。`auto`（既定）/ `powerpoint` / `libreoffice` / 任意のコマンド行。環境変数 `MD2PPTX_PDF_CONVERTER` を上書き |
| `--pdf-timeout SEC` | 変換を諦めるまでの秒数（`0` で無制限）。環境変数 `MD2PPTX_PDF_TIMEOUT` を上書き |
| `--watch` | 入力（と、そのテーマ・画像）が変わるたびに作り直し続ける。`Ctrl-C` で停止 |
| `--version` | バージョンを表示して終了（入力ファイルは不要） |

**出力は書き終わってから一度に差し替わります**（pptx も PDF も）。
作っている間も前回のファイルがそのまま読めるので、**PowerPoint や
PDF ビューアで開いたまま**何度作り直しても構いません。作りかけを掴むことはありません。

### PDF プレビュー（`--pdf`）

`--pdf` を付けると pptx に続けて PDF も書き出します（出力 pptx と同じ場所・同じ名前）。
Markdown を編集しながら PDF ビューアで結果を確認する、という使い方の土台です。

```bash
md2pptx slide.md --pdf
md2pptx slide.md --pdf-output preview.pdf  # PDF の名前や場所を変える（--pdf は不要）
```

- **PDF を作らせるのは `--pdf` と `--pdf-output` の2つ**です（両方指定したときは
  `--pdf-output` のパスに作ります）。
- `--pdf-output` には**存在するディレクトリ**を指定してください（無い場所を指すと
  PDF はできません）。
- **PDF 変換に失敗しても pptx は保存され、終了コードは0です**（警告は stderr に出ます）。
  編集しながらのプレビューを変換失敗で止めないためです。ただし**失敗したときは
  PDF を消す**ので、古い内容を新しい出力と取り違えることはありません。
- **PDF は変換中も一瞬たりとも消えません**（差し替えがアトミックなのに加えて）。
  多くのビューアはファイルが消えた時点で監視をやめてしまうので、
  「消してから書く」と開き直すまで自動リロードされなくなるためです。
- **変換が終わらないときの待ち方は、端末から実行しているかどうかで変わります。**
  端末から実行しているなら待ち続けます（承認ダイアログのように、
  応答すれば進むことがあるためです。やめたいときは `Ctrl-C`）。
  cron やエディタから実行したときのように**誰も応答できない場合は180秒で諦めます**。
  `--pdf-timeout SEC` と `MD2PPTX_PDF_TIMEOUT` で変えられます（`0` で無制限）。

#### 変換器（`--pdf-converter`）

既定の `auto` は**実 PowerPoint → LibreOffice** の順に、使えるものを選びます。

**任意のコマンド**も指定できます。`{input}`（pptx）/ `{output}`（PDF のパス）/ `{outdir}`
（その親ディレクトリ）が実際のパスに置き換わります。出力先を指定できないツールなら、
プレースホルダは書かなくて構いません。pptx のパスが末尾に付いて実行されるので、
**pptx と同じディレクトリに同じ名前で `.pdf` を書く**ツール（`slide.pptx` なら
`slide.pdf`）なら、そのまま使えます。

```bash
export MD2PPTX_PDF_CONVERTER='soffice --headless --convert-to pdf --outdir {outdir} {input}'
```

macOS で PowerPoint に変換させるときの注意です。

- **初回に「オートメーション」の承認**が要ります。
  PowerPoint を操作してよいか尋ねるダイアログが出るので、一度許可してください。
  承認は**呼び出し元アプリごと**（Terminal / iTerm / VS Code など）に別管理なので、
  実行元を変えると再度承認が要ります。
- **変換中に PowerPoint は表示しません。** そのため、
  承認ダイアログのような応答待ちは無音の停止にしか見えません。**30秒たっても終わらなければ、
  その旨を stderr に出します**（端末から実行しているときは PowerPoint も前面に出します）。
- **すでに PowerPoint を開いているときは、変換中にウィンドウが出ます。** 作業中の
  PowerPoint を勝手に隠さないための割り切りです（フォーカスは奪いません）。

### 編集しながら作り直す（`--watch`）

`--watch` を付けると起動したままになり、保存するたびに作り直します。
`--pdf` と組み合わせると、PDF ビューアを開いたまま原稿を書き進められます。

```bash
md2pptx slide.md --watch --pdf
```

```
md2pptx: watching slide.md — Ctrl-C to stop
md2pptx: 14:03:21 rebuilding slide.md
saved: slide.pptx slides: 14
saved: slide.pdf
md2pptx: 14:03:23 watching for changes
md2pptx: 14:04:07 rebuilding slide.md (fig.png changed)
```

- **見張るのは、そのビルドが実際に読んだファイル**です。
  Markdown だけでなく**テーマと画像**も含みます（テーマを差し替えれば作り直します）。
  原稿から画像を消せば、その画像はもう見ません。
- **まだ無いファイルも見張ります。** 「画像が見つからない」で失敗したあと、
  その画像を置けば作り直します。
- **書き込みが終わるのを待ってから作り直します。** ただし書き込みが10秒以上続いているときは、
  待たずに作りに行きます（理由を stderr に出します）。落ち着くのを待ち続けて何も起きないより、
  失敗してでも動いている方が分かるためです。
- **`--watch` は `--pdf` を含みません。** pptx だけを最新に保つ使い方も正当なので、
  PDF が要るときは `--pdf` を併記してください。
- **エラーで止まりません。** 文法エラーは表示するだけで、
  次の保存を待ちます（編集中は失敗しているのが普通の状態なので、
  ここで終了すると直しても誰も作り直してくれません）。ただし
  **起動時の引数の誤り**（入力ファイルが無いなど）はその場で終了します。
- **`Ctrl-C` で止まります**（終了コードは0）。エディタの「タスクの終了」などが送る
  `SIGTERM` でも同じように後片付けをしてから終わります。
- **速くなるわけではありません。** 1回のビルドはこれまでと同じで、
  手で起動しなくてよくなるだけです（時間の大半は PDF 変換で、常駐しても縮みません）。
- **PDF 変換が終わらないときは180秒で諦めます**（端末から実行していても）。
  見ているのはエディタと PDF であってこの端末ではないので、
  待ち続けると以後のプレビューが全部止まってしまうためです。止まった
  PowerPoint を前面に出すこともしません（編集画面を奪わないため）。
  `--pdf-timeout` で変えられます。

#### VS Code で編集しながらプレビューする

保存すると数秒で PDF のタブが更新される、
LaTeX Workshop のリアルタイムプレビューと同じ体験になります。
**設定と手順は [VSCODE.md](VSCODE.md) にまとめてあります**（タスク定義・PDF
ビューアの関連付け・通しの手順・つまずいたときの確認先）。

このリポジトリにも同じ `.vscode/` が入っているので、`example.md` ですぐ試せます。

### 試す

```bash
md2pptx example.md --theme OfficeTheme.pptx -o example.pptx
```

## Markdown 文法

### フロントマター（YAML）

ファイル冒頭を `---` で囲み、テーマ・出力先・タイトルスライド情報を書きます。
**`---`…`---` の内側は YAML、それ以降は Markdown 本文**として解釈されます（内側では
YAML の制約が効きます。後述の `{` の注意を参照）。

```yaml
---
theme: OfficeTheme.pptx   # デザインのおおもと（.thmx / .pptx）
output: out.pptx
slide_number: true                 # タイトル以外に番号を付与（既定 true）
default_autofit: true              # 本文があふれる場合に縮小（既定 true）

# タイトルスライド（あれば 1 枚目に生成）
title: |
  md2pptx
  Markdown でつくるスライド
subtitle: ― テーマ駆動のスライド生成 ―
author: md2pptx demo
affiliation:
  - Markdown ＋ PowerPoint テーマ → pptx
  - Python / python-pptx / PyYAML
---
```

- 使えるキーは上記の8つ（`theme` / `output` / `slide_number` / `default_autofit`
  / `title` / `subtitle` / `author` / `affiliation`）のみです。
  **未知のキーはタイポとみなしてエラーで停止**します。
- `title` の改行は多段タイトルになります。`subtitle` はタイトル枠内に少し小さめで入ります。
- `subtitle` / `author` / `affiliation` の各行は、先頭に本文と同じ相対サイズトークン
  `{+1}` / `{-1}`（後述）を置けます（例: 日付だけ一段小さく）。ただし **YAML では値が
  `{` で始まるとエラーになる**ため、トークン付きの行は `"…"` で囲んでください。
  例: `- "{-1} 2026年7月"`（本文中の `{+1}` はクォート不要です）。

### スライド分割とタイトル

- `# 見出し`（H1）はセクション見出しスライド（章の扉）
- `## 見出し` で新しいスライドを開始（見出し＝タイトル）。原稿のほとんどはこれになります
- `###` 以降（H3〜H6）は**未定義でエラー**（将来のスライド内小見出し用に予約）
- `---`（水平線）でも新しいスライドを開始します（タイトルなし）
- タイトル内に `<br>` を書くとその位置で改行
- 本文行（箇条書き・連番・矢印行など）内の `<br>` も同様にその位置で改行（段落内改行。
  続きの行は箇条書きのぶら下げ位置に揃います）

```markdown
## 行頭マーカー記法：<br>見た目で段落の種別を判定
```

どの書き方がテーマのどのレイアウトを使い、書いた文字がどの枠に入るかは
[THEME.md](THEME.md#どれを直すとどのスライドが変わるか) にまとめてあります。

### 本文：行頭マーカー記法

インデント（半角スペース2つ＝1レベル）でネストを表します。

| 書き方 | 表示 |
|---|---|
| `- テキスト` / `* テキスト` | 箇条書き（テーマ既定の記号） |
| `1. テキスト` | 自動採番 `1. 2. 3.` |
| `① テキスト` | 丸数字採番 `① ② ③`（番号文字は除去し自動採番に変換） |
| `(1) テキスト` | 丸括弧採番 `(1) (2)` |
| `→ テキスト` | 行頭記号なしの結論・補足行（`→` は表示に残る） |

- 丸数字マーカーは `①`（U+2460）〜`⑳`（U+2473）を認識します。
  他のマーカーと違い直後のスペースは省略できます（`①本文` も可）。
- `→` 行は「`→` ＋スペース1つ＋本文」へ正規化されます。

採番行の直下にネストした `-` を置くと「見出し＋説明」になります。

```markdown
1. parser.py
   - Markdown を中間表現（IR）へ変換
2. render.py
   - IR を pptx に描画
```

#### 行ごとの相対フォントサイズ

特定の行だけ強調・縮小したいときは、マーカー直後・本文直前に `{+1}` / `{-2}` を置きます。
**絶対 pt は指定できません**。テーマ既定サイズからの相対段数（1段 ≒ ±12.5%）だけを指定でき、
テーマを差し替えても比率が保たれます。

```markdown
- {+1} ここだけ一段大きく強調
- 通常の行
- {-2} 注記は二段小さく
① {+1} 採番行も大きくできる
→ {-1} 結論行も小さくできる
```

- 全行種（`-` / `1.` / `①` / `(1)` / `→`）で使えます。符号は省略可（`{2}` ＝ `{+2}`）。
- スライド全体を一律で調整するには `<!-- @body-size: -1 -->`（後述）。
  行の `{…}` が優先されます。`{0}` はスライドの `@body-size`
  を打ち消して「その行だけテーマ既定へ戻す」意味です（`@body-size: 0` は未指定と同義）。
- 見栄えはテーマに委ねる方針のため、これは“逃げ道”。
  常用せず強調したい一点に絞るのが推奨です。

### 表

Markdown 標準のテーブル記法。1行目をヘッダとしてアクセント色で着色します。

```markdown
## 課題の整理とアプローチ
<!-- @table-widths: 45,55 -->

体裁はテーマに、内容は Markdown に分離する

| 課題 | md2pptx のアプローチ |
|:--|--:|
| デザインの一貫性 | PowerPoint テーマに委譲 |
| 記述のしやすさ | Markdown の行頭マーカー記法 |

→ 色やフォントはコードに持たず、テーマに委ねる
```

- 導入文・結論文（地の文）はそのまま本文として置かれ、表は**その間に空く領域**に置かれます。
  以降この領域を**帯**と呼びます。地の文が片側だけなら残り全体、
  どちらも無ければ本文領域いっぱいを使います。
- `<!-- @table-widths: 45,55 -->` で列幅の比率を指定できます（既定は均等）。
- 区切り行のコロンで列ごとの水平寄せを指定できます：`:--:` 中央
  / `--:` 右 / `:--` 左（コロン無し `---` も左）。数値列の右寄せに便利です。
- 帯に収まらない表は、本文のフォントサイズを段階的に小さくして収めます。
  いちばん小さくしても収まらない場合は警告を出します（そのまま帯を超過しえます）。
  縮小せず標準サイズのまま下へはみ出したいときは `<!-- @overflow: true -->`
  （後述の「はみ出しの許可」）。

### フロー図

` ```flow ` フェンスブロックで box・矢印のフロー図を宣言的に記述します。

````markdown
## 生成パイプライン

```flow
direction: lr
note(top): テーマと Markdown を入力に pptx を生成
[theme.thmx | テーマ]
-変換-> [base.pptx | 土台]
-描画-> [out.pptx | スライド]
-> [… | ]
caption: 配色・フォントはテーマ、内容は Markdown
note(bottom): → テーマを差し替えるだけで見た目が一新できる
```
````

| 要素 | 記法 |
|---|---|
| ノード | `[ラベル \| サブラベル]`（サブラベル省略可） |
| 省略記号 | `[…]` または `[...]`（box ではなく中央寄せの注記） |
| 矢印 | `->` / ラベル付き `-PR->` |
| 方向 | `direction: lr`（左→右、既定）/ `tb`（上→下）。それ以外の値はエラー |
| 図のキャプション | `caption: …`（box の直下） |
| 上下の地の文 | `note(top): …` / `note(bottom): …`（本文プレースホルダへ） |
| 色の個別指定 | `[名前 \| サブ]{accent6}`（色名は後述のテーマ色名） |

ノード・矢印・設定行のいずれにも解釈できない記述はタイポとみなしてエラーで停止します。
色名に使えるのはテーマ色名 `accent1`〜`accent6` / `tx1` / `tx2` / `bg1` / `bg2`
です（`@autonum-color` と共通。無指定時はテーマから自動割り当て）。

### 画像（jpg / png）

画像は表・フロー図と同じ扱いで、導入文・結論文と一緒に1枚のスライドに置けます。
記法は2形式あります。

**ショートハンド（標準 Markdown 画像＋末尾 `{...}`）**

```markdown
![実験結果の比較](results.png){width=70%}
![](diagram.jpg){width=8cm align=left}
```

**フェンス ` ```image `（オプションが多いとき）**

````markdown
```image
src: results.png
width: 70%
crop: 100,50,800,400
align: center
caption: 実験結果の比較
```
````

| キー | 意味 |
|---|---|
| `src` | 画像ファイル（Markdown からの相対パス）。必須 |
| `width` / `height` | 埋め込みサイズ。`70%`（帯幅比）/ `8cm` / `300pt` / `2in`（`2"` も可）/ `150px` / 単位なし＝px。省略時はアスペクト自動 |
| `crop` | トリミング。**残す矩形 `x,y,w,h`**（左上原点）。既定はピクセル、各値に `%` を付けると割合 |
| `align` | 水平寄せ `left` / `center`（既定）/ `right` |
| `fit` | `width` と `height` を両方指定したとき `contain`（既定・比維持）/ `fill`（歪ませ充填） |
| `caption` | 図下キャプション（ショートハンドは alt テキストを採用） |
| `overflow` | `true` で帯からのはみ出しを許可（`width`/`height` の明示指定が必須・無指定はエラー。はみ出すのは下方向のみ）。未指定時はスライドの `@overflow` に従い、指定時はそちらより優先 |

- 画像パスは Markdown ファイルの置き場を基準に解決します。
  見つからない場合はエラーで停止します。
- 上記以外のキーはタイポとみなしてエラーで停止します。
- ショートハンドの `{...}` は空白区切りのため、空白を含むキャプションは
  alt テキスト（`![実験 結果](...)`）かフェンス記法の `caption:` を使ってください。
- `crop=100,50,800,400` は「左上 (100,50) から 幅800×高400 px
  の範囲を残す」の意味です（`crop=10%,5%,50%,40%` のように `%` でも指定できます）。
- 画像は自動的にアスペクト比を保ち、帯（中央領域）からはみ出さないよう収まります。
  `overflow: true` を指定すると明示した `width`/`height` を優先し、
  帯の下（結論文・罫線側）へのはみ出しを許可します（例: `height: 115%` で帯高の115%。
  上方向のタイトル・導入文には重なりません。`width`/`height` のどちらも無い場合はエラー、
  スライド下端を超える場合は警告を出力します）。
  指定サイズが帯に収まる場合（例: `height: 80%`）は通常配置と同じで、
  はみ出しは発生しません。

### 発表者ノート（` ```note `）

` ```note ` ブロックの中身が、そのスライドの発表者ノート（PowerPoint
の発表者ビューやノート印刷で見えるテキスト）になります。スライド面には表示されません。
オーラル原稿をスライドソースと同じファイルで版管理する用途を想定しています。

````markdown
## 背景：LaTeX論文執筆が抱える課題

- 学生側の障壁
  - OS差・TeX環境・パッケージ依存で環境構築が困難

```note
まず背景です．LaTeX の執筆環境は OS 差で環境構築が難しく，
指導のフィードバックも属人化しがちでした．
```
````

- スライド内ならどこに書いても構いません（読みやすさの点では末尾を推奨）。
  複数書くと改行で連結されます。ブロック内の改行は段落区切りとして保持されます。
- 最初の見出しより前（本文開始前）に置くと**タイトルスライドのノート**になります（フロントマターに
  `title:` が必要です）。

### 2カラム（「2 つのコンテンツ」）

`<!-- @col -->` を1つ置くと、その前後が左右2カラムに分かれ、
自動的に「2 つのコンテンツ」レイアウトになります。

```markdown
## 比較：手作業 と md2pptx

- 手作業でスライド作成
  - 体裁の調整に時間がかかる
  - デザインがばらつきやすい

<!-- @col -->

- md2pptx で生成
  - 内容（Markdown）に集中できる
  - テーマで見た目を統一
```

各カラムには箇条書き・採番だけでなく、**表・フロー図・画像**も置けます。
地の文（箇条書き）と表・図を同じカラムに混在させても重ならないよう配置され、
カラムに表・図しか無ければカラム全体に配置されます。左に要点、右に縦長の推移表、
といったレイアウトに使えます。

### ディレクティブ（任意の上書き）

行頭マーカーで表せない指定は、スライド先頭の HTML コメントで補います。

| ディレクティブ | 効果 |
|---|---|
| `<!-- @autonum-color: tx1 -->` | このスライドの採番記号色を指定（テーマ色名 `accent1`〜`accent6` / `tx1` / `tx2` / `bg1` / `bg2`） |
| `<!-- @layout: 5 -->` | レイアウト番号を上書き（**0から数える**。`5` はマスターの上から6番目） |
| `<!-- @autofit: 90 -->` | 本文を90% に縮小して焼き込む |
| `<!-- @body-size: -1 -->` | このスライドの本文を一律で相対調整（行の `{+1}` が優先） |
| `<!-- @table-widths: 45,55 -->` | 表の列幅比率（多カラムではスライド内の全カラムの表に共通適用） |
| `<!-- @col -->` | カラム区切り（「2 つのコンテンツ」レイアウトになる）。値は取らない |
| `<!-- @widths: 55,45 -->` | プレースホルダ幅（標準の使用可能幅に対する%）。値1個＝単カラム本文幅（例: `104`）、複数＝カラムごとの幅。合計>100で全体が拡幅 |
| `<!-- @overflow: true -->` | このスライドの表・画像に、帯（中央領域）から下方向へのはみ出しを許可（後述） |

- **未知のディレクティブはタイポとみなしてエラーで停止**します（行番号付き）。
- `@widths` の拡幅は**左端固定・右方向のみ**が既定（行頭位置がスライド間で揃う）。
  右余白で収まらない指定はクランプ＋警告になります。値の末尾に `!` を付ける（例: `108!`
  / `62,47!`）と、収まらない分だけ左余白へ逃がすことを許可します（スライド端は余白
  0.1in でクランプ）。
- 値の区切り・記号は全角（`，` `％` `！`）でも受理します。
  キー名のハイフンはアンダースコアと同一視します（`@body-size` ＝ `@body_size`）。
- 旧名称 `@ph-widths` / `@body-width`（→ `@widths`）と `@col-widths`（→ `@table-widths`）は
  v0.7 で廃止されました（エラーメッセージで新名称を案内します）。

#### はみ出しの許可（`@overflow`）

`<!-- @overflow: true -->` を置くと、
そのスライドの**表・画像**は「帯（中央領域）に収める」制約を外せます。共通の規約:

- **上端は帯の上端に固定**され、はみ出すのは**下（結論文・罫線側）のみ**。
  タイトル・導入文には重なりません。
- **表**: フォントを段階縮小せず、**本文標準（lvl1）サイズのまま**必要な高さで描画します。
  行数の多い表が読めないほど小さくなるのを防げます。
- **画像**: スライド既定として作用します。画像ブロックの
  `overflow:`（per-block）を明示した場合は**そちらが優先**されます。
  サイズ（`width`/`height`）の明示がない画像は帯に内接するため、
  `@overflow` を置いても変化しません。
- 帯に収まる表・画像には効果がありません（通常配置と同じ）。
- **結論文との重なりは仕様**です（結論文の帯に意図的に重ねる機能）。
  実際に重なる場合とスライド下端を超える場合は stderr に警告を出します。
- フロー図は対象外です（帯に内接固定。将来拡張）。
- 値は `true` / `false` のみ。それ以外はエラーで停止します。

## テーマについて

見た目はすべてテーマが決めます。**直し方は [THEME.md](THEME.md)**
にまとめてあります（配色・フォント・ロゴ・レイアウトの変え方と、確かめ方）。

- **`.pptx` を薦めます。** 開いて直して保存、で終わるからです。
  確認用のスライドを入れたままにもできます——md2pptx はテーマを土台としてだけ使い、
  中のスライドは出力に出しません。
- **`.thmx` も直接渡せます。** 組織で配布されたテーマがあるときはそのまま使えます。
  ただし **フルテーマ**（スライドマスター＋レイアウト同梱）である必要があり、
  色・フォントだけの簡易テーマはエラーになります。内部では base pptx に変換され、
  `--keep-base` で残せます。
- **レイアウトは並び順で選ばれます**（上から タイトル／`##` のスライド／`#` の章扉／2カラム）。
  スライドマスターで並べ替えると、出力が別のレイアウトで作られます。

## 制限・既知の差

- `@table-widths` はスライド単位の指定で、
  多カラムでは全カラムの表に同じ比率が適用されます（列数が比率の要素数と一致しない表は等幅のまま）。
  カラム分割比は既定ではレイアウト依存（通常50/50）ですが、
  `@widths` でスライド単位に変更できます。
- 表・図のフォントサイズや配置は概算見積もりに基づくため、
  実 PowerPoint の組版と完全一致はしません（安全側に縮小）。
- フロー図は横／縦一列のフローまで（分岐・格子は将来拡張）。
