# md2pptx

**Markdown と PowerPoint テーマ（pptx / thmx）から発表スライド（pptx）を生成するツール。**

スライドのデザインのおおもとは PowerPoint テーマで、配色・フォントはテーマに委ねます。
内容は Markdown で書き、行頭の見た目から段落種別（箇条書き・採番・結論行）を判定します。
表・フロー図・2カラム・タイトル改行にも対応します。

```
theme.pptx  ┐
            ├─▶  md2pptx  ─▶  out.pptx
input.md    ┘
```

## 特徴

- **テーマ駆動**：pptx（または thmx）の配色・フォント・レイアウトをそのまま使用
- **行頭マーカー記法**：`-` 箇条書き / `1.`・`①`・`(1)` 採番 / `→` 結論行 を見た目で自動変換
- **表**：Markdown 標準テーブル（ヘッダ着色・列幅指定）
- **フロー図**：独自の ` ```flow ` ブロックで box・矢印・キャプションを宣言的に記述
- **2カラム**：`<!-- @col -->` で「2 つのコンテンツ」レイアウト
- **発表者ノート**：` ```note ` ブロックでオーラル原稿をスライドと一緒に版管理
- **相対サイズ**：`{+1}`/`{-2}` で行ごとに強調・縮小（テーマ基準の相対段数のみ。絶対
  pt は持たない）
- **自動調整**：本文の標準フォントサイズに揃え、収まらない表・図は段階的に小さくして収める
- **はみ出し防止**：地の文がスライド外へあふれない

## 必要環境

- Python 3.11+
- [python-pptx](https://python-pptx.readthedocs.io/) 1.0 以上（インストール時に自動導入）
- [PyYAML](https://pyyaml.org/)（同上）

## インストール

`md2pptx` コマンドとして使えるようにするには、リポジトリのルートで次のいずれかを実行します。

```bash
# 推奨：pipx で隔離環境へインストール（依存も自動導入・PATH に md2pptx が入る）
pipx install .

# もしくは通常の pip（venv 推奨）
pip install .

# 開発用（編集が即反映される editable インストール）
pip install -e .
```

> pipx が無い場合は `brew install pipx`（macOS）や `python3 -m pip install --user pipx`
> で導入できます。インストールせずに試すだけなら、依存（`pip install python-pptx pyyaml`）を
> 入れたうえで `python3 -m md2pptx …` でも実行できます。

## クイックスタート

このリポジトリの `example.md` と `OfficeTheme.pptx` で、機能ひととおりのデモが作れます。

```bash
md2pptx example.md --theme OfficeTheme.pptx -o example.pptx
```

自分の原稿を作るときは次のように書きます。
テーマは自分で用意してください（→ [テーマについて](#テーマについて)）。

```bash
# テーマ（.pptx か .thmx）と Markdown を指定して pptx を生成
md2pptx input.md --theme theme.pptx -o out.pptx

# テーマ・出力先はフロントマターにも書ける（CLI 引数が優先）
md2pptx input.md

# 保存するたびに作り直し、PDF も書き出す
md2pptx slide.md --watch --pdf

# インストールせず開発中に実行する場合
python3 -m md2pptx input.md
```

**Markdown の書き方は [SYNTAX.md](SYNTAX.md) にまとめてあります**（早見表つき）。

## コマンドラインリファレンス

各オプションは次のとおりです。

| オプション | 説明 |
|---|---|
| 位置引数 | 入力 Markdown ファイル |
| `--theme PATH` | テーマファイル（`.pptx` / `.thmx` 両対応）。フロントマター `theme:` を上書き |
| `-o, --output PATH` | 出力 pptx。フロントマター `output:` を上書き |
| `--keep-base PATH` | `.thmx` から作る中間 base pptx を破棄せず保存（デバッグ用） |
| `--pdf` | pptx 生成後に PDF も作る。出力先は出力 pptx と同じ場所・同じ名前の `.pdf` |
| `--pdf-output PATH` | PDF の出力先を指定する。単独で指定しても PDF を作る（`--pdf` は不要） |
| `--pdf-converter NAME\|COMMAND` | PDF 変換器。`auto`（既定）/ `powerpoint` / `libreoffice` / 任意のコマンド行。環境変数 `MD2PPTX_PDF_CONVERTER` を上書き |
| `--pdf-timeout SEC` | 変換を諦めるまでの秒数（`0` で無制限）。環境変数 `MD2PPTX_PDF_TIMEOUT` を上書き |
| `--watch` | 入力（と、そのテーマ・画像）が変わるたびに作り直し続ける。`Ctrl-C` で停止 |
| `--version` | バージョンを表示して終了（入力ファイルは不要） |

**出力は書き終わってから一度に差し替わります**（pptx も PDF も）。
作っている間も前回のファイルがそのまま読めるので、**PowerPoint や
PDF ビューアで開いたまま**何度作り直しても構いません。作りかけを掴むことはありません。

### PDF プレビュー（`--pdf`）

`--pdf` を付けると pptx に続けて PDF も書き出します（出力 pptx と同じ場所・同じ名前）。
Markdown を編集しながら PDF ビューアで結果を確認する、という使い方の土台です。

```bash
md2pptx slide.md --pdf
md2pptx slide.md --pdf-output preview.pdf  # PDF の名前や場所を変える（--pdf は不要）
```

- **PDF を作らせるのは `--pdf` と `--pdf-output` の2つ**です（両方指定したときは
  `--pdf-output` のパスに作ります）。
- `--pdf-output` には**存在するディレクトリ**を指定してください（無い場所を指すと
  PDF はできません）。
- **PDF 変換に失敗しても pptx は保存され、終了コードは0です**（警告は stderr に出ます）。
  編集しながらのプレビューを変換失敗で止めないためです。ただし**失敗したときは
  PDF を消す**ので、古い内容を新しい出力と取り違えることはありません。
- **PDF は変換中も一瞬たりとも消えません**（差し替えがアトミックなのに加えて）。
  多くのビューアはファイルが消えた時点で監視をやめてしまうので、
  「消してから書く」と開き直すまで自動リロードされなくなるためです。
- **変換が終わらないときの待ち方は、端末から実行しているかどうかで変わります。**
  端末から実行しているなら待ち続けます（承認ダイアログのように、
  応答すれば進むことがあるためです。やめたいときは `Ctrl-C`）。
  cron やエディタから実行したときのように**誰も応答できない場合は180秒で諦めます**。
  `--pdf-timeout SEC` と `MD2PPTX_PDF_TIMEOUT` で変えられます（`0` で無制限）。

#### 変換器（`--pdf-converter`）

既定の `auto` は**実 PowerPoint → LibreOffice** の順に、使えるものを選びます。

**任意のコマンド**も指定できます。`{input}`（pptx）/ `{output}`（PDF のパス）/ `{outdir}`
（その親ディレクトリ）が実際のパスに置き換わります。出力先を指定できないツールなら、
プレースホルダは書かなくて構いません。pptx のパスが末尾に付いて実行されるので、
**pptx と同じディレクトリに同じ名前で `.pdf` を書く**ツール（`slide.pptx` なら
`slide.pdf`）なら、そのまま使えます。

```bash
export MD2PPTX_PDF_CONVERTER='soffice --headless --convert-to pdf --outdir {outdir} {input}'
```

macOS で PowerPoint に変換させるときの注意です。

- **初回に「オートメーション」の承認**が要ります。
  PowerPoint を操作してよいか尋ねるダイアログが出るので、一度許可してください。
  承認は**呼び出し元アプリごと**（Terminal / iTerm / VS Code など）に別管理なので、
  実行元を変えると再度承認が要ります。
- **変換中に PowerPoint は表示しません。** そのため、
  承認ダイアログのような応答待ちは無音の停止にしか見えません。**30秒たっても終わらなければ、
  その旨を stderr に出します**（端末から実行しているときは PowerPoint も前面に出します）。
- **すでに PowerPoint を開いているときは、変換中にウィンドウが出ます。** 作業中の
  PowerPoint を勝手に隠さないための割り切りです（フォーカスは奪いません）。

### 編集しながら作り直す（`--watch`）

`--watch` を付けると起動したままになり、保存するたびに作り直します。
`--pdf` と組み合わせると、PDF ビューアを開いたまま原稿を書き進められます。

```bash
md2pptx slide.md --watch --pdf
```

```
md2pptx: watching slide.md — Ctrl-C to stop
md2pptx: 14:03:21 rebuilding slide.md
saved: slide.pptx slides: 14
saved: slide.pdf
md2pptx: 14:03:23 watching for changes
md2pptx: 14:04:07 rebuilding slide.md (fig.png changed)
```

- **見張るのは、そのビルドが実際に読んだファイル**です。
  Markdown だけでなく**テーマと画像**も含みます（テーマを差し替えれば作り直します）。
  原稿から画像を消せば、その画像はもう見ません。
- **まだ無いファイルも見張ります。** 「画像が見つからない」で失敗したあと、
  その画像を置けば作り直します。
- **書き込みが終わるのを待ってから作り直します。** ただし書き込みが10秒以上続いているときは、
  待たずに作りに行きます（理由を stderr に出します）。落ち着くのを待ち続けて何も起きないより、
  失敗してでも動いている方が分かるためです。
- **エラーで止まりません。** 文法エラーは表示するだけで、
  次の保存を待ちます（編集中は失敗しているのが普通の状態なので、
  ここで終了すると直しても誰も作り直してくれません）。ただし
  **起動時の引数の誤り**（入力ファイルが無いなど）はその場で終了します。
- **`Ctrl-C` で止まります**（終了コードは0）。エディタの「タスクの終了」などが送る
  `SIGTERM` でも同じように後片付けをしてから終わります。
- **`--watch` は `--pdf` を含みません。** pptx だけを最新に保つ使い方も正当なので、
  PDF が要るときは `--pdf` を併記してください。
- **PDF 変換が終わらないときは180秒で諦めます**（端末から実行していても）。
  見ているのはエディタと PDF であってこの端末ではないので、
  待ち続けると以後のプレビューが全部止まってしまうためです。止まった
  PowerPoint を前面に出すこともしません（編集画面を奪わないため）。
  `--pdf-timeout` で変えられます。
- **速くなるわけではありません。** 1回のビルドはこれまでと同じで、
  手で起動しなくてよくなるだけです（時間の大半は PDF 変換で、常駐しても縮みません）。

#### VS Code で編集しながらプレビューする

保存すると数秒で PDF のタブが更新される、
LaTeX Workshop のリアルタイムプレビューと同じ体験になります。
**設定と手順は [VSCODE.md](VSCODE.md) にまとめてあります**（タスク定義・PDF
ビューアの関連付け・通しの手順・つまずいたときの確認先）。

このリポジトリにも同じ `.vscode/` が入っているので、`example.md` ですぐ試せます。

## テーマについて

見た目はすべてテーマが決めます。**直し方は [THEME.md](THEME.md)**
にまとめてあります（配色・フォント・ロゴ・レイアウトの変え方と、確かめ方）。

- **`.pptx` を薦めます。** 開いて直して保存、で終わるからです。
  確認用のスライドを入れたままにもできます——md2pptx はテーマを土台としてだけ使い、
  中のスライドは出力に出しません。
- **`.thmx` も直接渡せます。** 組織で配布されたテーマがあるときはそのまま使えます。
  ただし **フルテーマ**（スライドマスター＋レイアウト同梱）である必要があり、
  色・フォントだけの簡易テーマはエラーになります。内部では base pptx に変換され、
  `--keep-base` で残せます。
- **レイアウトは並び順で選ばれます**（スライドマスターの一覧で上から タイトル／`##`
  のスライド／`#` の章扉／2カラム）。並べ替えると、出力が別のレイアウトで作られます。

## 制限・既知の差

- `@table-widths` はスライド単位の指定で、
  多カラムでは全カラムの表に同じ比率が適用されます（列数が比率の要素数と一致しない表は等幅のまま）。
  カラム分割比は既定ではレイアウト依存（通常50/50）ですが、
  `@widths` でスライド単位に変更できます。
- 表・図のフォントサイズや配置は概算見積もりに基づくため、
  実 PowerPoint の組版と完全一致はしません（安全側に縮小）。
- フロー図は横／縦一列のフローまで（分岐・格子は将来拡張）。
